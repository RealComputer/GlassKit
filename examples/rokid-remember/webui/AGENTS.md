# Repository Guidelines

## Technology Stack
This web UI currently uses:

- React 19 + React DOM 19
- TypeScript 5
- Vite 7
- Tailwind CSS 4 via `@tailwindcss/vite`
- Motion (`motion`) for animation
- Heroicons React (`@heroicons/react`) for iconography
- ESLint 9 with `typescript-eslint`, `react-hooks`, and `react-refresh`

## Project Structure & Module Organization
This repository is a Vite + React + TypeScript web app. Work from the repo root.

- `src/`: application code (`main.tsx` entry, `App.tsx` root component, and styles).
- `public/`: static files served as-is (add files here only when they must keep a stable URL).
- `dist/`: production build output (generated by `npm run build`).
- Config files: `vite.config.ts` (includes Tailwind plugin), `eslint.config.js`, `tsconfig*.json`, and `index.html`.

Keep feature code in `src/` and prefer Tailwind utilities in JSX over component-specific CSS.

## Build, Test, and Development Commands
Run commands from the repository root:

- `npm install`: install dependencies.
- `npm run dev`: start local dev server with HMR.
- `npm run build`: type-check (`tsc -b`) and produce optimized build in `dist/`.
- `npm run lint`: run ESLint across the codebase.
- `npm run preview`: serve the built app locally for verification.

## Coding Style & Naming Conventions
Use TypeScript-first React patterns with functional components and hooks.

- Indentation: 2 spaces; keep semicolon usage consistent with existing files (currently no semicolons).
- Components: `PascalCase` filenames and exports (for example `UploadPanel.tsx`).
- Variables/functions/hooks: `camelCase` (hooks start with `use`, e.g., `useRecorderState`).
- Prefer small, focused components.
- Style components with Tailwind utility classes; keep `src/index.css` for global/base styles only.
- Follow `eslint.config.js` rules (`@eslint/js`, `typescript-eslint`, `react-hooks`, `react-refresh`).

## Testing Guidelines
There is currently no dedicated test script configured. For every change, treat these as required checks:

- `npm run lint`
- `npm run build`

If you add tests, colocate them as `*.test.tsx` next to the component or module they cover and include run instructions in the PR.

## Commit & Pull Request Guidelines
Use component-prefixed, imperative commit messages:

- Format: `<component>: <short summary>`
- Example: `webui: add recorder status indicator`

For pull requests, include:

- A clear summary of behavior changes.
- Linked issue/task (if available).
- Screenshots or short recordings for UI changes.
- The verification steps and commands you ran locally.
